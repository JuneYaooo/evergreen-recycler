# 排期规则与字段文档

本文档定义 evergreen-recycler 的输入输出契约与排期约束。脚本与本文档同步维护，
改动任一侧必须同步另一侧并跑 `python3 -m unittest discover tests`。

## 输入：posts.csv（历史帖子导出）

必需列（支持中文别名，大小写不敏感）：

| 规范字段 | 认得的别名 | 说明 |
| --- | --- | --- |
| `platform` | 平台 | xiaohongshu / douyin / weibo / wechat / bilibili / zhihu…（自由文本，同名单独统计） |
| `post_id` | 帖子id、笔记id、id、视频id | 防重复主键；无官方 ID 时用 URL 或标题 hash |
| `publish_date` | 发布日期、发布时间、日期 | 支持 `YYYY-MM-DD`、`YYYY/M/D`、`YYYY.M.D`、`YYYY年M月D日` |

可选列（缺失容忍，按 0 计入统计）：

| 规范字段 | 认得的别名 | 说明 |
| --- | --- | --- |
| `title` | 标题 | 排期表展示用 |
| `url` | 链接、地址 | 排期表跳转用 |
| `views` | 播放量、观看量、阅读量、浏览量、曝光 | 互动量主指标 |
| `likes` | 点赞、点赞数、赞、获赞、在看 | 默认权重 ×2 |
| `comments` | 评论、评论数、回复 | 默认权重 ×3 |
| `saves` | 收藏、收藏数、收藏量、collects、favorites | 默认权重 ×2（v0.3.0 起；列不存在时不影响结果） |
| `shares` | 转发、转发数、分享、分享数、reposts | 默认权重 ×3（v0.3.0 起；列不存在时不影响结果） |

坏行处理：缺 `post_id`、缺 `platform`、日期无法解析、**发布日期晚于基准日**（v0.3.0 起）
的行**跳过并在数据体检中计数**，不中断运行。缺部分数字字段按 0 计；**互动列全部为空**的行
（v0.3.0 起）保留计数，但不计入基线中位数、不参与赢家竞争，因为「没有数据」不等于「0 互动」。数据体检（有效行数、跳过原因、平台分布）始终是
排期表第一屏。

## 互动量与赢家判定

- 互动量 = `views + likes×2 + comments×3 + 收藏×2 + 转发×3`（权重可用 `--like-weight`、
  `--comment-weight`、`--save-weight`、`--share-weight` 调整）。收藏与点赞同权、转发与评论同权，
  沿用小红书 CES 第三方口径（赞 1 : 藏 1 : 评 4 : 转 4）的相对关系；该口径**不是平台官方公布**，
  只作为「收藏、转发不该被忽略」的依据。只在**同一平台内部**比较，跨平台不可比。
- 赢家口径二选一（`--metric`，报告与 CSV 会标注所用口径）：
  - `total`（默认）：**累计互动量**，v0.1.0 起的行为；
  - `per_day`：**日均互动量 = 互动量 ÷ max(距基准日存活天数, 1)**，修正老帖靠
    时间累积的天然优势；发布当天或日期晚于基准日按 1 天计（单日爆发的极新帖
    会被放大，取舍自负）。
- 基线二选一（`--baseline`，v0.3.0 起）：
  - `platform`（默认）：同平台全部帖子的中位数与分位数，v0.2.0 行为；
  - `rolling`：同平台**发布日期最近的 N 条**（`--rolling-window`，默认 20，不含自身）。
    同期帖子的存活时长和账号体量相近，相当于 vidIQ「同一时间段」、Overseer「同帖龄比较」的近似。
    分位数按「自身在 窗口+自身 中的位置」计算。
  - 数据体检会对每个平台算「最新 1/3 帖子中位数 ÷ 最早 1/3 帖子中位数」（≥9 条才算），
    ≥2 或 ≤0.5 时提示基线漂移，并建议加跑 rolling。
- 赢家 = 口径值 ≥ 基线中位数 ×`--median-x`（默认 3.0）**且** ≥ 基线
  P`--min-percentile`（默认 75）。两条同时满足，避免长尾爆款或平庸头部误判。3x 与同类工具一致
  （OutlierKit「3x+ 显著」、Overseer「3-5x strong outlier」）。
- 平台样本 < `--min-sample`（默认 10）条 → **降级**：赢家照常识别，但只标记不排期
  （按样本条数计数，与口径无关）。
- 账号总有效帖 < 20 条 → 冷启动：不排期，输出「先攒数据」建议。
- 每条赢家附「口径标注 + 基线倍数 + 分位数排名」，供博主自行复核判断。

## 排期硬约束（全部参数化，默认取保守值）

| 约束 | 默认 | 参数 | 依据 |
| --- | --- | --- | --- |
| 每平台排期密度 | 任意 7 天 ≤3 条 | `--weekly-cap` | ReQueue 常青组「3 条/周起步」经验值 |
| 同帖距上次发布（**含首发**）间隔 | ≥60 天 | `--recycle-gap-days` | 常青工具的回收间隔多在 45-90 天，60-90 天最常见（UniLink、SocialBu），取下沿；首发也算一次发布，对应 Revive Old Posts「最小帖龄」 |
| 同帖累计再发次数 | 不限（0） | `--max-recycles` | CoSchedule 发送上限、SmarterQueue 过期、SocialBu 2-5 次；建议 3-5 |
| 同平台排期日间隔 | ≥1 天 | `--min-gap-days` | 避免同平台连发刷屏 |
| 赢家阈值 | 中位数 ≥3x 且 ≥P75 | `--median-x` / `--min-percentile` | 相对自身基线，避开跨账号粉丝量不可比 |
| 赢家口径 | 累计互动量（`--metric total`，默认）；日均互动量（`--metric per_day`） | `--metric` | 日均口径修正老帖的累积优势；两者都在平台内比较 |
| 基线 | 平台全量（`platform`）；滚动（`rolling`，最近 20 条） | `--baseline` / `--rolling-window` | 账号体量变化大时全量中位数失真 |
| 样本门槛 | ≥10 条/平台 | `--min-sample` | 分位数在小样本上不稳；Vamos 同样要求 ≥10 条才显示 outlier 分数 |

时效提示：标题出现年份（如「2025 年」）、节日、大促、直播、抽奖、限时等词时，理由位标
「⚠ 疑似时效」，CSV 的 `time_sensitive_hint` 写入命中词。**只提示不剔除**，由 Agent 和用户确认
内容是否仍然成立（依据：SocialBu 建议跳过绑定日期/活动的帖子）。

排期算法：赢家按基线倍数降序（同倍数比互动量、再比 post_id，保证确定性）贪心入槽，
放不下的进「已标记、本期待定」并给出原因（配额满 / 再发间隔未到 / 距首发不足 / 次数达上限 / 样本不足）。

## ledger.json（已再发记录，可选输入）

```json
{
  "wb_002": ["2026-03-15", "2026-07-01"],
  "xhs_003": ["2026-08-30"]
}
```

- 键为 `post_id`，值为该帖历史**再发日期**数组（不含首发日）。
- 脚本取 max(首发日, 最近一次再发日)，若「该日期 + `--recycle-gap-days`」落在规划期内，
  排期自动顺延到其后；超出规划期则进待定列表。`--max-recycles` > 0 时，再发次数达到上限的帖子
  直接进待定。
- 建议由用户在每次变体重发后手动追加日期，或把上期 schedule.csv 中已执行的行回填。

## 输出

- **排期表 Markdown**（`-o`）：数据体检 → 各平台排期表（排期日、原帖数据、基线倍数、
  距首发、再发窗口、理由位、文案变体方向空栏）→ 已标记待定 → 边界说明。
- **schedule.csv**（`--csv`）：机器可读，列含
  `planned_date, platform, post_id, title, url, publish_date, views, likes, comments,
  engagement, metric, metric_value, median_multiple, percentile_rank, days_since_publish,
  days_since_previous, reason_hint, variant_direction, status, baseline, saves, shares,
  time_sensitive_hint`（最后 4 列为 v0.3.0 追加，按列名读取的旧表格不受影响）。`metric`/
  `metric_value` 为所选口径及其比较值（`engagement` 恒为累计互动量）；
  `variant_direction` 留空由 Agent 填写，`status`（pending/done/skipped）由博主回填。
- **汇总 JSON**（`--json`）：模式、参数（`params.metric`/`baseline`/`rolling_window`/
  `max_recycles` 等）、数据体检（含 `no_metric_rows`、`extra_metric_columns`）、
  各平台 `baseline_drift_ratio`、
  各平台统计（`median_engagement` 恒为累计口径中位数，`median_metric_value` 为
  所选口径中位数）、排期与待定清单。
